## 2. 定位与总体结构

交换芯片的 **精确匹配（Exact Match）查表引擎**：按 key（如 MAC 48 位）查动作数据（AD）。
采用业界 EM 引擎常见的**三级组织**，并支持按需裁剪：

```
        io.key(Valid)                                            io.rsp(Valid: hit+ad)
             │                                                          ▲
        ┌────▼─────┐   ┌──────────────┐   ┌─────────────┐   ┌────────────┴───────┐
        │ key FIFO │──►│  查找 FSM    │──►│  CR C/哈希   │──►│  EmLayout 位宽/字段 │
        └──────────┘   │  (lk*)       │   └─────────────┘   └────────────────────┘
                       └──┬────────┬──┘
   io.wr(Valid) ──────────┼────────┼──────── 维护 FSM (mt*)
   learnPend ─────────────┘        │
                                   │
        ┌──────────────┬───────────┴──┬──────────────┬───────────┐
        │  HT（哈希桶） │   KT（key）   │  AD（动作）   │  OVFC     │
        │ numBanks 个   │  1 个         │  1 个         │ 寄存器阵列 │
        │ TpMemoryWrap3 │ TpMemoryWrap3 │ SpMemoryWrap3 │ (TCAM)    │
        └──────────────┴──────────────┴──────────────┴───────────┘
                       ▲
        sweep FSM (sw*, 老化) 复用 HT/KT 读端口
```

| 级别 | 存储 | 内容 | 物理实现 |
|------|------|------|----------|
| **HT** | Hash Table | 桶，存"指向 KT 的指针"（或内联 key/AD） | `numBanks` 个 `TpMemoryWrap3`（每 d-left 子表一个，双口） |
| **KT** | Key Table | 完整 key + 指向 AD 的指针（或内联 AD） | 1 个 `TpMemoryWrap3`（**单实例**，读口分时复用） |
| **AD** | Action Data | 动作数据 | 1 个 `SpMemoryWrap3`（单口，写优先） |
| **OVFC** | Overflow TCAM | HT 溢出条目（key + 负载） | 寄存器阵列，并行比较 |

三级可裁剪：`useKt=false` → key 内联进 HT（单级表）；`useAd=false` → AD 内联进 KT（两级表）。

**d-left（`numBanks>1`）**：一次哈希切成 `numBanks` 段子表索引；插入时选"占用最少"的子表，
显著提高装填率。`numBanks=1` 退化为普通组相联哈希表。

## 3. 参数与位宽布局

### 3.1 `EmParams`

| 参数 | 默认 | 说明 |
|------|------|------|
| `keyWidth` / `adWidth` | 48 / 32 | 查找 key 位宽 / 动作数据位宽 |
| `htDepth` / `htWays` | 1024 / 4 | HT 总桶数（被 `numBanks` 均分）/ 每桶路数 |
| `numBanks` | 1 | d-left 子表数（1 = 关闭） |
| `dLeftTie` | `Random` | 并列仲裁：`Leftmost` / `Random`（16 位 LFSR）/ `RoundRobin` |
| `ktDepth` | 4096 | KT 总条目数 |
| `useKt` | true | false = key 内联进 HT |
| `adDepth` / `useAd` | 1024 / true | AD 条目数 / false = AD 内联进 KT |
| `ovfcDepth` | 0 | HT 溢出 TCAM 深度（0 = 关闭） |
| `crcWidth` / `crc` | 32 / `CrcHardwired.crc32` | 哈希位宽 / 哈希算法形态 |
| `keyFifoDepth` | 2 | key 输入 FIFO 深度 |
| `aging` | None | `AgingParams(ageWidth, timeout, tickDiv, sweepEnable)` |
| `learning` | None | `LearningParams(defaultAd, usePortAd)` |
| `memProtect` | `ProtNone` | 透传给 `Memory.protect`（ECC/Parity） |

`EmLayout` 内 `require` 的硬约束：`htDepth/ktDepth/adDepth/bankDepth` 必须为 2 的幂
（`Memory.addrWidth = log2Ceil(depth)`，非 2 的幂会产生越界地址）；`htDepth % numBanks == 0`；
`idxW*numBanks <= crcWidth`。

### 3.2 位宽推导（`EmLayout`）

| 字段 | 公式 | 说明 |
|------|------|------|
| `bankDepth` | `htDepth / numBanks` | 每个 HT bank 的桶数 |
| `idxW` | `max(1, log2Ceil(bankDepth))` | 桶索引位宽 |
| `bankW` / `wayW` | `max(1, log2Ceil(numBanks))` / `max(1, log2Ceil(ways))` | 至少 1 位，避免 0 宽 |
| `slotW` / `scanW` | `max(1, log2Ceil(numBanks*ways))` / `+1 位` | 扁平槽位号；扫描游标要多 1 位以表达"扫完" |
| `ktBanks` | `numBanks * ways` | **一次查找最多要串行读的候选槽数**（非物理 bank 数） |
| `ktPtrW` / `adPtrW` | `log2Ceil(ktDepth)` / `log2Ceil(adDepth)` | 指针位宽 |
| `htEntryW` | `1 + ageW + htPayW` | `[0]=valid, [ageW:1]=ts, 高位=负载` |
| `htWordW` | `htEntryW * ways` | **一个 HT word = 一整桶** |
| `ktEntryW` | `keyW + ktPayW` | `[keyW-1:0]=key, 高位=adPtr 或 ad` |
| `lookupLatency` | `1 + (useKt ? ktBanks : 0) + (useAd ? 1 : 0)` | **理想流水深度，非实际 FSM 拍数**（见 §6.5） |

字段访问器全部集中在 `EmLayout`（`htValid/htTs/htPay/htKtPtr/htKey/htAdPtr/htAd/ktKey/ktAdPtr/ktAd/slotBank/slotWay`），
上层不重复拆位。

## 4. 对外接口（`EmIo`）

| 端口 | 方向 | 语义 |
|------|------|------|
| `key: Valid[UInt(keyW)]` | in | 查表请求。**无 ready，无背压**；FIFO 满时丢弃并累加 `status.keyDrop` |
| `rsp: Valid[UInt(1+adW)]` | out | 查表结果：`Cat(hit, ad)`，命中 1 拍脉冲 |
| `wr: Valid[EmWrCmd]` | in | 维护口：`op`(add/del/upd) + `key` + `ad`。**无 ready**，`wrBusy` 期间下发会被静默丢弃 |
| `wrBusy: Bool` | out | `mState =/= MT_IDLE \|\| learnPend` |
| `learnAd: UInt(adW)` | in | 自学习时用作新条目的 AD（通常是入端口） |
| `learnEn: Bool` | in | 自学习运行时开关 |
| `ageEn: Bool` | in | 老化运行时开关（同时门控命中刷新与 sweep 删除） |
| `memInit: Bool` / `memInitDone: Bool` | in/out | 广播到各级 `dfx.init`；`initDone` 全高且 `!memInit` 才算 ready |
| `crcPoly/crcInit/crcXor: UInt(crcW)` | in | 仅 `CrcRuntime` 模式生效 |
| `status: EmStatus` | out | 见 §11 |

`memReady`（Level 0 门控）出现在每个 FSM 的状态推进条件里：**存储初始化完成前所有 FSM 停住**。

## 5. 存储组织与端口

### 5.1 实例

| 实例 | 配置 | 数量 |
|------|------|------|
| `EmHt0..N` | `TpMemoryWrap3`，`htWordW` 位 × `bankDepth` | `numBanks` |
| `EmKt` | `TpMemoryWrap3`，`ktEntryW` 位 × `ktDepth` | 1 |
| `EmAd` | `SpMemoryWrap3`，`adW` 位 × `adDepth` | 1 |

统一 `Memory(...)` 配置：`flopIn=false, flopOut=false, CheckIn=false, CheckOut=false`
→ `latency=1`，`rdLat = 1`（`ExactMatch.scala:103`）。**换真 SRAM 只需改这里的配置**，
FSM 通过 `pend` 计数器按 `rdLat` 等读，不写死拍数。
`cpu`/`dfx` 侧端口由 `driveAux` 统一置无效；`dfx.init` 接 `io.memInit`。

### 5.2 读端口仲裁（`pend` 计数器）

三路读源，优先级 **查找 > 维护 > sweep**：

| 存储 | 请求条件 | 仲裁 |
|------|----------|------|
| HT | `lkState===LK_HT` / `MT_HT` / `SW_RD` | `htGrant{Lk,Mt,Sw}` 组合产生，grant 拍 `htRdPend := htLat` |
| KT | `LK_KTF` 或 (`LK_KT` && 该候选 valid) / `MT_KTF` 或 (`MT_KT` && …) / `SW_KTF` | 同上（`ktGrant*`） |
| AD | `lkState===LK_AD` | 单口：`mtAdWrReq`（写优先）压制 `adGrantRd` |

⚠️ 两个已踩过的坑（代码注释保留）：

1. **"本拍 grant"优先级必须最高**：owner 寄存器在 grant 拍末才更新，只看 owner 会让 grant 当拍用到上一个 owner 的地址。
2. **复用 owner 判占用时必须同时要求 `pend≠0`**：owner 寄存器初值为 0（lookup），空闲时会把 lookup 的垃圾地址选中。

### 5.3 写端口优先级

- **HT**（每个 bank 独立）：`mt`（`mtWantsHt`）> `sw`（`swState===SW_WR`）> `rf`（命中刷新 `lkState===LK_REF`）。
  三者共用同一写口，`selMt`/`selSw` 通过 Mux 抢地址与数据；被压制的 `sw` 会停在 `SW_WR` 等下一拍重试。
- **KT**：仅维护插入写（`mState===MT_WR && !mFound && useKt`）。
- **AD**：维护写优先于查找读（`adRdPend===0` 才让查找发读）。

### 5.4 `FreeList`

`KT` / `AD` 各一个全局空闲栈：初始化为恒等映射，`sp=depth` 表示全空闲；
`alloc` 弹栈、`free` 压栈；同一拍同时 alloc+free 时净数量不变（把归还地址直接塞进刚挖出的坑）。
**实现为寄存器数组（行为模型），大 depth 时应换成 bitmap + 优先编码器。**

## 6. 时序与 FSM

### 6.1 查找 FSM（`lk*`）

```
LK_IDLE ──(memReady && qDeq.valid)──► LK_HASH[串行CRC] ──► LK_HT
   ▲                                      └─(固化CRC 直接)──► LK_HT
   │                                                 │ htGrantLk
   │                                                 ▼
   │                                              LK_HTW ──(pend==1&&owner==0)──► LK_CMP
   │                                                                               │
   │                        ┌── OVFC 命中 ──► LK_KTF（单次取指）──────────────────┤
   │                        ├── HT 扫描到候选 ──► LK_KT（逐候选串行）──┐            │
   │                        └── 无候选 ─────────────────────────────►│            │
   │                                                                 ▼            │
   │                                                              LK_AD ◄──────────┘（useAd）
   │                                                                 │ adGrantRd
   │                                                                 ▼
   │                                                              LK_ADW ──(pend==1)──► LK_REF
   └────────────(hit && ageEn)──────────────────────────────────────────────────────────┤
                                LK_DONE ◄──── (miss 或 !ageEn) ──────────────────────────┘
```

- `LK_CMP` 与 `LK_HTW` **必须分两拍**：捕获是寄存器写，当拍读到的还是旧值（寄存器初值 X 时 `when(X)` 会污染状态寄存器）。
- OVFC 命中优先于 HT 候选；OVFC 命中记 `lkHitInOvfc=true`，刷新走寄存器而非 HT 写口。
- `!useKt` 时在 `LK_CMP` 做 4 路（`ktBanks` 路）**并行** key 比较（`lkInlineCmp`）。
- `LK_KT` 逐个候选读 KT 并比较 key，命中即止；不命中则 `nextFrom(valid, scanIdx+1)` 找下一个候选。

### 6.2 维护 FSM（`mt*`）

```
MT_IDLE ─(io.wr.valid 或 learnPend)─► MT_HASH ─► MT_HT ─► MT_HTW ─► MT_CMP
                                                                      │
        ┌── 命中 OVFC ──► MT_KTF ───────────────┐                        │
        ├── 命中 HT   ──► MT_KT ────────────────┤                        │
        └── 未命中 ─────────────────────────────┼──────► MT_DEC ◄────────┘
                                                │            │
                     ┌── found：del ──► MT_FREE ─┤            │
                     │   found：add/upd ─► MT_WR ┤            │
                     │   未命中 & del ──► MT_IDLE（幂等）      │
                     │   未命中 & upd ──► MT_IDLE（insFail++） │
                     └── 未命中 & add ─► MT_ALLOC ─► MT_WR ───┘
```

- d-left 选桶在 `MT_DEC` 用 `mCounts`（各子表 PopCount）+ 并列策略（`tieBase`）求出 `mBestBank`/`mFreeWay`；
  `mHasFree=false` 时落到 OVFC（`mUseOvfc=true`），OVFC 也满则 `insFail++`。
- `MT_ALLOC` 从 `FreeList` 取 KT/AD 指针；指针耗尽同样 `insFail++`。
- `MT_FREE` 归还 KT/AD 指针并清 HT valid（`mNewEntry` 的 valid 由 `mState===MT_WR` 决定）。
- 自学习请求（`learnPend`）与 `io.wr` 在 `MT_IDLE` 中**仲裁，维护口优先**；学习固定为 `add`。

### 6.3 老化 sweep FSM（`sw*`）

```
SW_IDLE ─(memReady)─► SW_RD ─grant─► SW_RDW ─pend==1─► SW_SCAN
   ▲                                                     │
   │                          ┌── 过期 && useKt ──► SW_KTF ─┐
   │                          ├── 过期 && !useKt ─► SW_FREE ┤
   │                          ├── 本桶还有路 ──► swW++ ──────┤（留在 SW_SCAN）
   │                          └── 本桶扫完 ──► 下一桶 ──────┤
   │                                                        ▼
   │                                                     SW_FREE ─(swFreeOk)─► SW_WR ─(!mtWantsHt)─► 下一路/桶
   └─────────────(全部扫完)──── SW_OV[ovfcEn] ─(swOvIdx==ovfcD)──────────────────────────┘
```

- 逐 bank、逐桶、逐路（way）扫描 HT；游标 `(swB, swI, swW)`，扫完自动回到 `SW_IDLE` 并**立即重新开始**
  （即持续后台扫描，即使 `ageEn=0` 也会占读端口）。
- 过期判据：`ageEn && valid && (now - ts) >= timeout`；**未启用老化时恒判不过期**
  （不能拿 `timeout=0` 兜底，否则全表被删）。
- ⚠️ 不能写 `when(swW < ways.U)`：`swW` 位宽只有 `wayW` 位，永远 `< ways`，会导致"换下一桶"分支被折叠成不可达代码。

### 6.4 时间基准

`tick` 每拍 +1，到 `tickDiv-1` 归零并令 `now := now + 1`（`now` 为 `ageWidth` 位）。
命中时写回 `now`（LRU 型老化），插入时写 `now`。

### 6.5 延迟与吞吐（`rdLat=1` 时静态推导）

| 路径 | 拍数 | 轨迹（从 `LK_IDLE` 接受算起） |
|------|------|-------------------------------|
| 接受 → HT 数据捕获 | 3 | `IDLE(0) → HT(1) → HTW(2) → CMP(3)` |
| 每个 KT 候选 | **2** | `KT` 发读 1 拍 + 下一拍比较/换候选 |
| KT 扫描（最坏 `ktBanks` 个） | `2*ktBanks` | —— |
| miss 响应 | `5 + 2*ktBanks` | `…CMP(3) → KT×2N → DONE` |
| hit 且在第一个候选 | ~9（含 AD+REF） | `KT(2) → AD(2) → REF(1) → DONE(1)` |
| `CrcRuntime` | **+keyWidth** | 串行 LFSR 逐位，`lkState===LK_HASH` 阻塞 |

| preset | `ktBanks` | `lookupLatency`（理想） | 实测最坏 miss 拍数（推导） |
|--------|-----------|------------------------|---------------------------|
| `basic` (1 bank×4 way) | 4 | 6 | **12** |
| `2left` (2 bank×4 way) | 8 | 10 | **20** |
| `inline` (useKt=F) | 4 | 1 | ~4 |
| `noad` (useAd=F) | 4 | 5 | ~11 |
| `crcrt` | 4 | 6 | +48（串行 CRC） |
| `tb` | 4 | 6 | **12** |

> `EmLayout.lookupLatency` 只是"理想流水深度"，**低估了实际 FSM 周期数**（每个 KT 候选实际 2 拍、
> HT/AD 各 2 拍）。文档/上层建模若按它算吞吐会偏差 ~2 倍。

**吞吐结论**：`rsp` 与"接受下一个请求"共用同一个 `LK_IDLE` 状态，即**单请求串行引擎**：
稳态吞吐 = 1 请求 / (miss 12 拍 或 hit 9~12 拍)，`2left` 更差。**不是每拍一请求。**

## 7. 老化（Aging）

- 时间戳法：插入写 `ts=now`，命中刷新 `ts=now`（`LK_REF`），sweep 扫 `now - ts >= timeout`。
- 过期后的动作链（**HT 分支**）：
  1. `SW_SCAN` 判定过期 → `SW_KTF`（读 KT，仅为了拿到 AD 指针，`useAd` 时才需要）
  2. `SW_FREE` → **同一拍**归还 KT 指针（`ktFree.faddr = htKtPtr(swE)`）与 AD 指针（`ktAdPtr(swKtData)` 或 `htAdPtr(swE)`）
  3. `SW_WR` → 清 HT 条目 valid（`htEntry(false, now, pay)`），`entryCnt--`，`ageDrop++`
- **OVFC 分支**（`SW_OV`）：`ovfcV(i) := false`（同一拍归还 KT/AD），`ovfcUseCnt--`，`entryCnt--`，`ageDrop++`。
- 与维护删除互斥：`swFreeOk = mState =/= MT_FREE`，不满足时停在 `SW_FREE` 重试（避免同一地址被二次释放）。

## 8. 自学习（Learning）

`LK_DONE` 检测到 `!hitReg && learnEn` → 置 `learnPend`、锁存 `learnKey`；维护 FSM 在 `MT_IDLE` 取走并执行
`add`，AD 取 `learnAd`（`usePortAd`）或 `defaultAd`。计数 `status.learn`。

`learnPend` 参与 `io.wrBusy`，但**不阻塞新的查找**——查找 FSM 会立刻接受下一个请求（见 §15.2）。

## 9. d-left 与并列仲裁（`TiePolicy`）

多个子表占用数并列时选谁：

| 策略 | 行为 | 评价 |
|------|------|------|
| `Leftmost` | 取最左 | 最简，但轻载时几乎每次都并列为 0 → **条目全堆在 bank0，d-left 负载均衡完全失效**（实测：9 条全落 bank0） |
| `Random` | 16 位 LFSR 挑一个并列者 | 经典 d-left 做法，装填率最高（默认） |
| `RoundRobin` | 轮转，仅插入时前进 | 确定性、各子表均匀，**便于验证断言** |

实现：`mMinCnt` 求最小占用 → `mMinMask` → 从 `tieBase` 开始环形找第一个达标子表（`mBestBank`）。

## 10. OVFC（HT 溢出 TCAM）

- 结构：`ovfcV/ovfcK/ovfcP/ovfcT` 寄存器阵列（valid / key / 负载 / 时间戳）+ `ovfcUseCnt`。
  `ovfcP` 位宽与 HT 负载同构（`ktPtrW` 或 `adPtrW` 或 `adW`），KV 分开存放以便并行 CAM 比较。
- 查找：`ovfcMatch(key)` 并行比较 → `PriorityEncoder` 选最小编号，**OVFC 命中优先于 HT 候选**。
- 插入：HT 桶满（`mHasFree=false`）且 OVFC 有空位时落入 OVFC；OVFC 条目的 KT/AD 同样从 `FreeList` 分配。
- 覆盖：`mFound && mInOvfc` 时只刷新时间戳与 AD，不动 valid。
- 删除/老化：清 `ovfcV`，归还 KT/AD，`ovfcUseCnt--`。
- 位宽陷阱：`ovfcSelW`（选择）与 `ovfcCntW`（计数）必须分开——计数要能表达 `ovfcDepth` 本身（=扫描终点），
  否则扫描游标永远到不了终点（实测踩过）。

## 12. CRC / 哈希（`Crc.scala`）

统一形态"左移 MSB 先"，poly 的 bit i = x^i 系数（x^width 隐含）；`refin` 输入 LSB 先喂、`refout` 输出按位反转，
组合起来即标准 reflected CRC（以太网 CRC-32）。

| 形态 | 参数 | 硬件 | 延迟 | 面积 |
|------|------|------|------|------|
| `CrcHardwired` | elaboration 期已知 | 逐位展开成纯 XOR 树 | 组合，0 拍 | `width*dataWidth` 个门（48×32≈1536） |
| `CrcRuntime` | CSR 改写 poly/init/xorout | 串行 LFSR `CrcSerial` | `dataWidth` 拍 | 小 |

- 固化 CRC 每个 bit 迭代：`fb = st(msb) ^ in_bit`，`new_st(i) = st(i-1) ^ (poly(i) & fb)`。
- 哈希切分：`slices(h) = h[(b+1)*idxW-1 : b*idxW]`，一次哈希供 `numBanks` 个子表使用。
- 查找与维护**各用一个 CRC 实例**（`lkCrc`/`mtCrc`），可并行哈希，互不阻塞。
- 注意：只用到哈希的**低位** `idxW*numBanks` 位；`crcWidth` 远大于 `hashW` 时高位被浪费。

---

## 13. 空闲条目栈（`FreeList`）

见 §5.4。语义：`sp = 空闲数`，`alloc` 弹栈给 `stack(sp-1)`，`free` 压入 `stack(sp)`；
同时 alloc+free 时净数量不变，把归还地址直接塞进刚挖出的坑。`ok = (sp =/= 0)`。

## 15. 功能符合性检查（2026-09-17）

### 15.1 需求 1：支持每拍处理一个请求 —— ❌ **不满足**

| 检查项 | 结论 |
|--------|------|
| 是否有流水线 | 无。`ExactMatch.scala:232-282` 只有一组 `lkState` 状态寄存器 |
| 接受节奏 | `qDeq.ready` **仅在 `LK_IDLE` 拉高**（`ExactMatch.scala:227`、`443-451`）；处理期间不接受新请求 |
| 响应节奏 | `io.rsp.valid` 仅在 `LK_DONE` 拉高 1 拍，随后回 `LK_IDLE` |
| 稳态吞吐 | 1 请求 / (miss 12 拍、hit 9~12 拍)；`2left` ≈ 1/20 拍 |

**根因**：KT 是单实例存储，`ktBanks = numBanks*ways` 个候选**逐槽串行读**，每槽 2 拍。
代码注释里原本设计为"KT 按 (bank,way) 分成 numBanks*ways 个物理 bank，查找时必然落在不同 bank、无端口冲突"
（`EmParams.scala:143-148`），但现实现改成了单实例 + 串行扫描，这是吞吐的主要瓶颈。

**附带问题**：两个入口都**无背压**——`io.key`(Valid) FIFO 满时丢请求（只累加 `keyDrop`）；
`io.wr`(Valid) 在 `wrBusy` 期间被静默丢弃（连计数都没有）。即便上游每拍一个请求，也无法保证不丢。

**若要满足**：需要真正的多请求流水线（每级 valid/bits 打拍、N 个 in-flight 上下文），
并把 KT 恢复成按 `(bank,way)` 分 bank 的并行读 + 桶内候选并行比较；否则应在文档/接口上明确
"EM 是低延迟串行引擎，吞吐 1/(9~12) 拍"。

---

### 15.2 需求 2：背靠背两个同 KEY 请求，第一个 Miss，第二个可以 Hit —— ❌ **不满足**

设 `learnEn=1`、表中无 key K。两个请求 A、B 同 K，A 在 cycle 0 被接受，B 紧随其后入 FIFO。

```
cycle  0       A 接受（LK_IDLE→LK_HT），keyReg=K
       1..N    A 走 HT→HTW→CMP→（无候选）→LK_DONE → 响应 miss
       N      LK_DONE：learnPend:=1, learnKey:=K；lkState:=LK_IDLE
       N+1    ● 查找 FSM 立刻接受 B（LK_IDLE 不检查 mState）
              ● 维护 FSM 同拍进入 MT_HASH（自学习插入开始）
       N+1..  B：HT 读（lookup 有读口优先权）→ 桶内此刻仍无有效条目 → miss
       N+4    B 响应 miss
       N+8~9  维护 FSM 才走完 HASH→HT→HTW→CMP→DEC→ALLOC→WR，HT 条目落盘
```

**结论**：第二个请求在第一个的插入落盘**之前**就完成了查找，**一定 miss**。
原因不是偶发竞态，而是结构性的：插入要 8~9 拍，而背靠背查找只占 4 拍；且 `LK_IDLE`
不等待 `learnPend`/`mState`，两者并行推进。

**要让第二个 Hit，需要其中之一**：
1. **转发/旁路**：在 `LK_CMP` 处增查一个小的"在途插入 buffer"（pending insert CAM，key+AD），命中即当作 hit 返回；
2. **读等待**：`LK_IDLE` 在被查 key 与 `learnKey` 相同时等待 `learnPend` 完成（简单但引入停顿）；
3. **旁路寄存器**：插入写 HT 的同时写一个单条影子寄存器，查找先比影子（只能覆盖 1 条在途）。

---

### 15.3 需求 3：支持 HT 老化，老化满足后同时释放 KT 资源 —— ⚠️ **基本满足，但有 3 个缺陷**

**满足的部分**（`ExactMatch.scala:819-864`）：

| 步骤 | 状态 | 动作 |
|------|------|------|
| 判定过期 | `SW_SCAN` | `ageEn && valid && (now-ts) >= timeout` |
| 取 KT 中 AD 指针 | `SW_KTF` | `ktRdPend==1 && ktRdOwner==2` 时 `swKtData := ktMem.rdata` |
| **同时释放 KT + AD** | `SW_FREE` | `ktFree.free` 与 `adFree.free` **同一拍**；`swFreeOk` 互斥维护删除 |
| 清 HT valid | `SW_WR` | `htEntry(false, now, pay)` + `entryCnt--` + `ageDrop++` |

单元路径正确：**老化判定成立后，KT 与 AD 指针在同一拍归还 FreeList**，HT 条目随后失效。
`useKt=false` 时跳过 KT 步骤直接 `SW_FREE`；`useAd=false` 时只还 KT。

**缺陷 1（功能性 Bug）：`swOvIdx` 未初始化 → OVFC 扫描可能死循环，进而卡死整个 sweep**

`ExactMatch.scala:282` `val swOvIdx = Reg(UInt(l.ovfcCntW.W))` **无 `RegInit`**，且进入 `SW_OV`
的两个转移点（`:826`、`:854`）都**没有清零**。在 4 态仿真（iverilog，EmGen 的目标仿真器）中该寄存器为 X：

- `swOvIdx === ovfcD.U` → X，判 false；
- `swOvExpired(X)` → 索引 `ovfcV(X)` → X，判 false；
- 落到 `otherwise: swOvIdx := swOvIdx + 1` → 仍是 X。

→ **永远出不了 `SW_OV`**。由于 `SW_OV` 之后才回 `SW_IDLE` 重启扫描，这会导致**第一次全表扫完之后
整个 sweep 停止**，HT 老化随之失效（`tb` / 任何 `ovfcDepth>0` 的配置）。Verilator（2 态）会初始化为 0 而"看起来正常"，
属于典型的仿真器相关隐雷。

**已用产出 Verilog 核对**（`sbt "runMain em.EmGen out/em tb"` → `out/em/tb/ExactMatch.v`）：

```verilog
reg  [3:0] swOvIdx;                      // :2810 无初始化
// reset 分支（:3165-3184）列出了 lkState/mState/swState/... 但没有 swOvIdx
wire _GEN_12 = swOvIdx == 4'h8;          // :2899 与 ovfcD=8 比较
swOvIdx <= swOvIdx + 4'h1;               // :3583/3585 两个分支合并后仍只是自增
```

且该文件 `initial` 块数量为 0（`--disable-all-randomization` 不补初值）。
**修法**：在进入 `SW_OV` 时 `swOvIdx := 0.U`（或给 `RegInit(0.U)` 并在 `SW_IDLE` 清零）。

**缺陷 2（时序窗口）：KT/AD 已归还，HT 条目还 valid 一拍**

`SW_FREE` 归还指针、`SW_WR` 才清 valid，中间隔 1 拍。此窗口内若命中该 HT 条目，
会读到已归还的 KT 槽：key 比较通常失配 → 报 miss（不错但浪费），
若该槽恰好被同一 key 重新占用则报 hit（语义上也正确）。**窗口本身不会产生假命中**，
但与缺陷 3 叠加会放大后果。

**缺陷 3（竞态）：命中刷新（`LK_REF`）可"复活"已被老化的条目 → KT/AD 双重释放**

`LK_REF` 无条件把 `htEntry(true, now, htPay(rfEntry))` 写回 `(lkHitBk, lkHitWy)`
（`ExactMatch.scala:364-366`、`541-548`），只做了**同拍写口互斥**（`!mtWantsHt && !swWantsHt` 时前进），
**没有跨拍顺序保护**：

```
cycle T    lookup 读 HT 桶，捕获到条目 E（valid）
cycle T+k  sweep 在同一 (bank,idx,way) 判定过期 → SW_FREE 归还 E 的 KT/AD → SW_WR 清 valid
cycle T+m  lookup 走到 LK_REF，把 E 以 valid=1 写回（m>k）
```

后果：HT 条目"复活"但 KT/AD 已被归还，可能已被别的条目重新分配 → 该 HT 条目变成
**悬挂指针 + 资源泄漏**；后续对同一地址的删除/老化会触发 **FreeList 二次压栈**，
两次 alloc 返回同一地址 → 两个 key 共享同一 KT/AD 槽 → 静默数据错乱。
注意该竞态只在 `ageEn=1`（即老化真正启用、`LK_REF` 也启用）时成立，**正是目标工作模式**。

**修法（择一）**：
- 给每 bank 加一个 sweep 世代计数 `swGen(b)`，lookup 在 `LK_HTW` 锁存，`LK_REF` 只有世代未变才写回（推荐，代价小）；
- sweep 在 `SW_WR` 记录 `(bank,idx,way)`，`LK_REF` 命中同一槽时放弃刷新；
- 把"清 HT valid"提前到 `SW_FREE` 与归还指针同拍完成（消除缺陷 2 的窗口，但**不能**单独解决缺陷 3）。

**其他观察**（不影响正确性）：`useKt && !useAd` 时仍会走 `SW_KTF` 读一次 KT，但结果只用于取 AD 指针 → 该次读完全多余；
`ageEn=0` 时 sweep 仍持续全表扫描，白白占用 HT/KT 读端口。

## 16. 已知设计约束与注意事项（速查）

| 主题 | 约束 |
|------|------|
| 地址位宽 | `htDepth/ktDepth/adDepth/bankDepth` 必须 2 的幂（`Memory.addrWidth=log2Ceil`） |
| `ways==1` | 路编号 0 位，槽位拆位退化为 `s = b`，不能写 `s >> 1`（`EmParams.scala:200-206`） |
| 捕获/裁决分拍 | `LK_HTW` 与 `LK_CMP` 必须分开，否则读到旧值 / X 污染状态 |
| owner 判占用 | 必须同时要求 `pend≠0`，否则空闲时误选 lookup 垃圾地址 |
| 位宽退化 | `swW < ways.U` 因位宽不足恒真，会让分支不可达（必须用 `=== ways-1`） |
| 计数位宽 | 扫描游标位宽要能表达"终点"（`+1` 位；OVFC 计数 `log2Ceil(depth+1)`） |
| 未启用功能的寄存器 | `ovfc*` 在 `ovfcEn=false` 时是 `null`，必须在 **Scala 层**收掉分支，不能只靠 `when` |
| 老化兜底 | `aging=None` 时过期判据必须恒 false，不能用 `timeout=0` |
| iverilog | 必须 `disallowLocalVariables`，否则不出 vvp |
